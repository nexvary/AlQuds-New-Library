# ترحيل البيانات في النسخة التجريبية 1.4.1

## الهدف والتوافق

هوية الحزمة `org.alquds.library` محفوظة. يرتفع versionCode إلى 16 ومخطط SQLite من 1 إلى 2. لا إعادة بناء للفهرس أو حذف صفوفه. تنشأ `favorites(book_id)` بمفتاح أجنبي إلى books وحذف تابع، و`local_state(key,value)` لتسجيل الاستيراد. تبقى حقول وعلاقات وفهارس وحقوق الكتب الموجودة كما هي.

## الانتقال

1. ينفذ SQLiteOpenHelper إنشاء الجدولين ورفع user_version داخل معاملة واحدة. فشل أي CREATE يلغي التغيير كله ويحتفظ بالإصدار 1 والصفوف السابقة. لا DROP أو حذف ملف كحل بديل.
2. بعد فتح المخطط 2، تُستورد قيم `favorite.<id>=true` من SharedPreferences الخاصة بالتطبيق داخل معاملة منفصلة. تقبل فقط قيم Boolean الحقيقية وأرقام كتب موجودة. لا تستورد مفاتيح تالفة أو قيماً نصية أو مراجع محذوفة؛ تظل مفضلة الكتاب المؤرشف محفوظة لكن لا يظهر في نتائج القراءة.
3. تسجل المعاملة `favorites_imported_v1` بعد نجاح الاستيراد فقط. لا تُحذف إعدادات المفضلة القديمة أو الثيم. فشل الاستيراد يُبقي القيم الأصلية وعلامة الاستيراد غائبة فتُعاد المحاولة عند الفتح التالي.
4. بعد اكتمال الاستيراد تكون SQLite مصدر المفضلة الوحيد؛ إزالة مفضلة لا تعود بسبب القيمة القديمة عند إعادة فتح التطبيق. الكتاب الجديد الذي لم يكن موجوداً وقت الاستيراد لا يحصل تلقائياً على قيمة قديمة غير صالحة.
5. قراءة المفضلة وحفظها خارج خيط الواجهة. يحدث فلتر المفضلة في SQL قبل LIMIT 100. فشل الكتابة لا يظهر للمستخدم كنجاح ولا يحذف بياناته.

## التراجع

الرجوع التلقائي إلى مخطط أقدم مرفوض دون حذف. الإعدادات القديمة ليست نسخة احتياطية لعمليات المفضلة الجديدة بعد الترقية. أي رجوع إلى APK قديم يحتاج مسار استعادة متوافق ونسخة احتياطية معتمدة قبل نشر إنتاجي؛ لا إلغاء لترحيل مخطط 2 داخل التطبيق الحالي. مفاتيح توقيع debug ليست سياسة توقيع إنتاج، ولم يُنشر هذا التغيير إنتاجياً.

## التحقق

`app/src/androidTest/assets/catalog-v1.sql` لقطة مستقلة لمخطط 1 مع كتابين وISBN وحقوق وأرشفة وبيانات عربية؛ لا تُولّد من كود مخطط 2. تفحص اختبارات Android الترقية وحفظ الصفوف واستيراد القيم الصحيحة مرة واحدة والاحتفاظ بالتفضيلات، وتراجع المعاملة عند تعارض الجدول الثاني بعد نجاح إنشاء الأول. تفحص اختبارات القاعدة والواجهة حفظ وإزالة المفضلة وحد النتائج وأخطاء الكتابة. يختبر برنامج force-stop استمرار SQLite والثيم عبر عمليتين. نتائج CI مطلوبة قبل اعتماد المرحلة.
